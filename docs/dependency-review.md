# UI dependency review — 2026-11-07

Scope: the six open GitHub Dependabot alerts for `ui/package-lock.json`, plus the additional minimatch advisory returned by a current npm audit. No forced overrides, production changes, or advisory dismissals.

## Fixed

- **happy-dom 20.14.6 → 21.0.4** (direct development dependency). Addresses [GHSA-834v-8h66-3h79](https://github.com/advisories/GHSA-834v-8h66-3h79) (host code execution through import aliases) and [GHSA-c8p4-j97h-3vg8](https://github.com/advisories/GHSA-c8p4-j97h-3vg8) (SSRF from HTML parsing). Used by the Vitest/Nuxt component test environment, not the deployed server. Both installed test-tool peer ranges accept 21.0.4; its Node >=20 floor is below Forge's Node 24 build runtime.
- **mermaid 11.17.2 → 12.2.0**, resolving **katex 0.16.47 → 0.18.10** through Mermaid's supported `^0.18.0` dependency. Addresses [GHSA-238p-pmpm-9mq7](https://github.com/advisories/GHSA-238p-pmpm-9mq7). The vulnerable path requires existing prototype pollution to bypass KaTeX trust checks. Mermaid is client-side and lazy-loaded for bundled help-document diagrams; `help-diagrams.ts` sets strict security and `htmlLabels:false`. Patched dependency is preferable to treating those constraints as a fix. Latest Mermaid 11 still requires vulnerable KaTeX ^0.16.47; no incompatible override used. [Mermaid 12 release notes](https://github.com/mermaid-js/mermaid/releases/tag/mermaid%4012.0.0): Node >=22.12, Safari >=17.4/ES2024, new layout/look defaults. Forge preserves existing appearance with `layout:'dagre'`, `look:'classic'` and validates help diagrams. Existing initialize/render APIs remain supported.

## Remaining upstream advisories

- **glob 13.0.6 and 10.5.0** — [GHSA-3g3m-2fjr-6pw4](https://github.com/advisories/GHSA-3g3m-2fjr-6pw4), moderate, fixed in 14.0.2. Paths: `@vue/test-utils → js-beautify → glob`; `nuxt → @nuxt/nitro-server → nitropack → @vercel/nft → glob`; `nitropack → archiver → archiver-utils → glob`. Latest js-beautify 2.0.3 requires ^13.0.6 and @vercel/nft 1.11.1 requires ^13.0.0, so no supported complete upgrade exists. Vulnerability is traversal continuing after AbortSignal cancellation. Inspected NFT's two calls in `out/analyze.js`: no signal option. js-beautify's CLI calls globSync without signal; Vue's formatter uses the beautify library, not that CLI. These are build/test paths, not UI request handlers. Nitro 2.13.6 would remove the old archiver/glob10 subtree but leaves glob13, so omitted incidental churn from this release change. No claim that arbitrary uses of glob are safe.
- **esbuild 0.27.7** — [GHSA-g7r4-m6w7-qqqr](https://github.com/advisories/GHSA-g7r4-m6w7-qqqr), low, fixed in 0.28.1. `@nuxt/ui → @nuxt/fonts 0.14.0 → fontless 0.2.1 → esbuild ^0.27.0`; other build tools share it. Even latest @nuxt/ui 4.12 retains @nuxt/fonts ^0.14.0. Advisory requires esbuild's development server using `servedir` on **Windows**. Forge builds its UI in a Node24 Linux container and runs the bundled Nitro server; it does not serve production with esbuild. Nitro separately already has esbuild0.28.2. Updating Vite/unplugin would not remove fontless's constraint, so no unrelated upgrades or forced0.28 override.
- **deepmerge 4.3.1** — [GHSA-gcqx-w48m-w2h4](https://github.com/advisories/GHSA-gcqx-w48m-w2h4), low, no patched release. `nuxt → @nuxt/nitro-server → nitropack → @rollup/plugin-node-resolve16.0.3 → deepmerge`. Inspected the resolver's only call: `deepFreeze(deepMerge({}, defaults))`, where defaults is a source-code literal containing fixed arrays/booleans. User opts use object spread separately. The reported malicious-source-object premise is absent at this call. Build dependency; no untrusted request object reaches it. Keep tracked until upstream fixes/removes it; npm audit's suggested Nuxt downgrade is inappropriate.
- **minimatch 9.0.9 and 10.2.6** — [GHSA-g3hv-75wg-m249](https://github.com/advisories/GHSA-g3hv-75wg-m249), moderate, newly returned by npm audit, fixed in11.0.1. Paths: `vue-tsc2.2.12 → @vue/language-core → minimatch9`; `js-beautify → editorconfig3.0.2 → minimatch10`; `glob13 → minimatch10` and `archiver-utils → glob10 → minimatch9`. Globparts amplification can exhaust resources with adversarial patterns. Inspected Vue usages take patterns from Vue compiler config; editorconfig takes repository config patterns. Build/typecheck/format paths, not operator web requests. Upstream ranges exclude11; upgrading only vue-tsc would still leave others and adds an unrelated major-version change. No override.

## Validation and release limits

The combined validation used Node 24 and a fresh `npm ci`. Typechecking and the production build passed. Of 623 component tests, 622 passed initially; the remaining help-length check passed after shortening the runtime guide (31 help tests passed on rerun). All 47 browser suites passed, including Help diagrams, onboarding, account recovery and settings. The mobile Help rendering was also inspected. The current npm audit still reports 19 affected dependency nodes (3 low, 16 moderate), representing the four underlying advisories above. This is not a clean audit or a substitute for reviewing third-party distribution terms.
